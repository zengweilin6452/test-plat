# TestDock 首期核心流程与交付验收规格

Status: ready-for-agent

## Problem Statement

测试人员需要通过浏览器使用 Android 真机完成测试，而不必靠命令行拼接任务、设备和结果。目前平台已有任务、设备、执行、报告、性能分析和调试能力，但代码完成、历史测试通过与当前版本通过端到端验收是不同状态。可信套件来源未配置时，用户无法登记真实 UI 套件；固定代码快照是否实际被执行、真实联动采集、近期改动后的调试体验和首期完整回归都需要明确证据。

## Solution

以单工作空间、同机 Android 首期为边界，先确认并修复任务从可信套件来源到固定代码快照的实际执行链路，再用隔离测试数据和明确授权的设备走通 UI、独立性能及联动运行。最后核对调试、报告、资源独占和页面状态，并以当前版本、条件、证据及未通过原因形成可追溯的交付验收记录。已有能力先核验再修改；发现本范围内的缺陷应修复并复验。

## User Stories

1. 作为测试人员，我希望看到可用的可信套件来源，以便选择受控代码。
2. 作为测试人员，我希望没有来源时看到明确提示，以便知道需要什么配置。
3. 作为维护者，我希望来源由宿主预先配置，以免浏览器指定任意宿主路径。
4. 作为测试人员，我希望登记测试套件并发现用例，以便在页面选择测试输入。
5. 作为测试人员，我希望每次发现生成固定套件版本，以便追溯执行内容。
6. 作为测试人员，我希望版本固定代码快照，即使来源随后变化也执行原内容。
7. 作为维护者，我希望缺失或损坏的代码快照阻断执行，以免悄悄运行其他代码。
8. 作为测试人员，我希望选择应用和构建版本，以便确认测试对象。
9. 作为测试人员，我希望核对设备已安装应用的身份，以便发现版本不一致。
10. 作为测试人员，我希望确认首次识别的身份基准，以便后续运行复核。
11. 作为测试人员，我希望看到身份不可读取或不一致的原因，以便修正后重试。
12. 作为测试人员，我希望创建并验证任务修订，以便固定运行配置。
13. 作为测试人员，我希望从已验证修订启动运行，并跟踪状态、进度和事件。
14. 作为测试人员，我希望取消运行并看到最终状态，以便知道设备何时释放。
15. 作为测试人员，我希望设备已被占用时排队或拒绝，以免两个操作争用设备。
16. 作为测试人员，我希望查看失败截图、日志和断言，以便定位失败。
17. 作为测试人员，我希望报告能追溯构建、任务修订、套件版本、资源档案与证据。
18. 作为测试人员，我希望独立性能运行采集指定指标和时长，以便分析应用性能。
19. 作为测试人员，我希望样本或可比条件不足时看到未判定及具体原因，以免误读为通过。
20. 作为测试人员，我希望基线按应用和资源档案比较，以便理解结果是否可比。
21. 作为测试人员，我希望规则试算保留原始判定和历史报告，以便安全比较方案。
22. 作为测试人员，我希望联动运行在同一次 UI 执行期间采集性能，以便关联操作与性能。
23. 作为测试人员，我希望联动运行分别展示 UI 和性能结果及异常原因。
24. 作为测试人员，我希望调试会话显示实际设备、实时画面和连接状态。
25. 作为测试人员，我希望冻结同一次画面和节点树，以便准确定位。
26. 作为测试人员，我希望框选图片后先验证真实匹配，再登记图像模板版本。
27. 作为测试人员，我希望刷新或恢复预览后清除旧匹配和颜色框，以免误读画面。
28. 作为测试人员，我希望模板跨会话可查，并能在任务修订中固定版本。
29. 作为测试人员，我希望异常、空态和不可用操作有明确说明，以便知道下一步。
30. 作为验收人员，我希望每项结论记录版本、测试条件和证据，以便区分历史结果与本次结果。
31. 作为维护者，我希望外部服务或设备不可用时记录阻塞原因，不把未执行记为通过。

## Implementation Decisions

- 沿用已批准的首期目标和领域术语：应用、构建版本、套件版本、代码快照、任务修订、运行、运行组件、资源档案及原始判定分别表达，不混用任务状态和运行结论。
- 按依赖顺序推进：核对可信套件来源及固定代码执行，贯通 Android UI 任务，再验收独立性能与联动，最后完成调试、页面及交付回归。来源为空是当前环境状态，应记录；不得自行引入新的数据来源、安装依赖或选择未经授权的宿主目录。隔离测试可使用受控测试夹具；真实来源的配置由用户提供或另行授权。
- 已有实现不是空白项目。当前派发器准备并传入固定副本根，但执行器当前的工作目录和 pytest 目标路径尚未看到消费该根的接线；将此作为具体待核实和修复项，不以注释或历史工单勾选代替执行证据。UI 与联动复用的执行路径均须核对。
- 固定副本的发现和真实执行必须指向同一版本；相对导入、本地模块、pytest 配置和选定用例必须在受控副本边界内解析。来源改变不能改变已有版本；副本缺失、摘要不符、越界或执行输入不可用时明确阻断，不退回可变来源。报告或事件记录实际版本与摘要；依赖环境不因代码快照被误称为已锁定。
- 继续使用现有构建登记、身份核对、任务修订、运行、设备租约、报告和套件接口，只有现有契约不足时才做最小必要扩展。身份确认和运行前复核不得绕开资源独占；不能将版本信息核对描述为 APK 字节摘要验证。
- 独立性能使用固定性能场景，不假称执行了 UI 动作。联动使用同一次资源独占和同一次 UI 执行，采集窗口覆盖实际执行；分别保存两个组件的真实结果，采集、执行、取消或基础设施失败均按实际状态呈现。
- 原始判定、证据和运行快照不可被重分析覆盖；缺失指标不补零，未判定展示真实原因。保留已有报告检索、分页、部分证据、重跑和下载能力。
- 调试保持只读，沿用设备租约、真实预览、冻结快照、节点与图像匹配。框选验证使用真实新画面，成功后才允许从当前框选登记；框选、阈值、快照或会话改变后必须重新验证。刷新或恢复预览清除临时选择、验证结果和颜色框，不删除已登记模板。
- 页面验收以当前原型和已批准规格为依据，注明参考版本；真实数据所需的加载、空态、错误与不可用状态如实显示。已批准的布局例外及用户后续明确要求优先于历史截图。
- 本规格是实施与验收范围说明，不自动授权安装依赖、改变依赖版本、增加外部来源、提交、推送、发布或修改 vendor；真机动作和隔离数据准备需符合会话中已有授权，缺失授权或设备条件时如实记录阻塞。

## Testing Decisions

- 以用户确认的页面到真实后端完整流程作为最高层验收入口；复用现有 API、执行器和设备适配测试作为定位边界。优先测试可观察行为与持久结果，不以私有函数调用次数或与实现逐行对应的测试代替验收。
- 使用隔离数据库、受控测试套件和临时产物目录；记录测试版本、设备、来源、运行标识、操作和证据。不得覆盖共享库中的用户数据，测试结束仅清理自己创建且可识别的资源。
- 用不同标记的固定副本和后来修改的来源验证：发现、执行输出及报告指向原副本；覆盖副本缺失、篡改、路径越界、套件依赖及相对导入。复用现有套件发现、执行接线和运行提交测试作为先例。
- 通过页面或真实接口验证构建身份、任务验证、运行跟踪、取消和资源释放；使用现有租约、运行生命周期、设备同步及报告测试覆盖失败、排队、占用与并发的既有契约。
- 在可用真机上分别验证 UI、独立性能和联动，记录采集与 UI 执行的时间关系、组件结果、证据及报告。模拟测试可验证失败矩阵，但不得冒充真机验证；不可用时标记具体未执行项。
- 验证原始判定与试算分离、基线可比、缺失指标和未判定原因；覆盖证据可用、缺失、过期及下载状态，并复用现有分析和报告测试。
- 对近期调试交互检查设备选择、会话关闭与释放、冻结、节点拾取、框选验证、登记、刷新及恢复预览；检查匹配结果与当前画面的对应关系。页面视觉在目标 Windows 环境检查必要窗口尺寸、缩放和键鼠操作。
- 执行适合最终变更的前端构建、相关测试及后端回归；测试基础设施失败需记录真实原因与未执行范围，不用历史通过或跳过的测试充数。复用当前有效证据，只在代码或条件发生变化时重测受影响部分。

## Out of Scope

多用户登录、组织及细粒度权限；Web/iOS 真实执行；跨机器调度；实时性能曲线；对象存储；应用 CRUD、上传或自动安装；设备自动修复；调试触控；修改 vendor 源码。以上需要独立需求或现有规划中的后续阶段，不因本规格自动开工。

## Further Notes

- 现有对齐规格和本地工单保留历史决策和证据；工单状态、勾选和历史验收不等于当前 HEAD 的交付验收。
- 已有 2026-10-31 的 Android 真机调试历史记录；近期 UI、图像验证和设备同步变动需要针对受影响行为取得当前证据。
- 当前环境曾观察到可信套件来源为空，且后端全量测试的临时数据库启动失败；执行前重新核实，不把历史现象当成当前必然状态。
- 推荐交付物是一份验收记录，逐项标明已通过、已实现待验、未完成或受阻，以及具体版本和证据；发现的范围内缺陷修复后记录复验。
