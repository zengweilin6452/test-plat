# TestDock 首个可交付版本收口规格

Status: ready-for-agent

日期：2026-11-08

## Problem Statement

平台已经具备项目与应用管理、任务修订、真实执行、性能判定、设备调试和报告追溯等主要能力，但实现、工单状态与验收证据尚未完全同步。使用者仍无法从一份明确的结论判断：当前版本能否在新 Windows 环境部署，能否从首次使用走到真实运行，以及哪些能力仍受设备或环境限制。

已有历史验证不能一概视为当前通过，也不能因为汇总记录过时而全部重跑。近期交互修复需要补齐实际浏览器行为证据，部署迁移和整体验收仍有明确缺口。

## Solution

以现有能力形成首个可交付版本：校准剩余工作，补齐真实使用、Windows 交互、部署与升级验收，修复这些流程中发现的范围内缺陷，最终提供可追溯的版本验收结论与使用说明。

继续沿用当前架构和依赖，各阶段完成后已有平台保持可用。优先完成已有功能的交付条件，不重新实施旧开发计划，也不以扩展新功能代替收口。

## User Stories

1. 作为项目维护者，我希望每项工作都有准确的完成、待验或受阻状态，以便判断真实剩余工作。
2. 作为项目维护者，我希望每项通过结论能追溯到版本、环境和证据，以便避免把历史结果当作当前验证。
3. 作为项目维护者，我希望复用条件仍成立的历史证据，以便避免无意义的重复测试。
4. 作为首次使用者，我希望正式初始化后得到干净环境，以便不会把演示数据误认为真实业务。
5. 作为首次使用者，我希望通过页面设置工作空间、创建项目并登记应用，以便建立自己的测试对象。
6. 作为测试人员，我希望登记明确的构建版本与可信套件版本，以便运行依据可以追溯。
7. 作为测试人员，我希望缺少可信来源、设备或性能前置条件时看到准确原因，以便知道如何继续。
8. 作为测试人员，我希望从页面完成测试任务配置和真实 UI 运行，以便不必依赖命令行完成日常测试。
9. 作为测试人员，我希望故意失败的用例保留失败结论及证据产物，以便定位问题。
10. 作为测试人员，我希望性能运行展示真实采集结果，以便判断性能表现。
11. 作为测试人员，我希望缺失指标不显示为零、未判定附带原因，以便不会误判结果。
12. 作为测试人员，我希望联动运行的性能窗口覆盖 UI 执行并保留两个运行组件的结果，以便分析同一次执行。
13. 作为测试人员，我希望同一资源的运行与调试保持互斥，以便不会互相干扰。
14. 作为测试人员，我希望取消和执行错误如实显示，并释放占用，以便继续使用设备。
15. 作为测试人员，我希望调试预览、冻结快照和定位操作正常工作，以便准备和核查测试。
16. 作为测试人员，我希望结束调试后设备能用于下一次运行，以便不留下无效占用。
17. 作为报告使用者，我希望报告关联任务修订、构建版本、套件版本、资源及证据产物，以便核查结果来源。
18. 作为报告使用者，我希望在线报告可阅读、相关图表可呈现、证据可访问，以便完成实际分析。
19. 作为报告使用者，我希望重分析保留原始判定，以便历史结论不被覆盖。
20. 作为多项目使用者，我希望切换项目、跨页导航和刷新后范围保持正确，以便不混用其他项目的数据与选择。
21. 作为多项目使用者，我希望同名应用和冲突链接得到明确处理，以便不会操作错误的测试对象。
22. 作为使用者，我希望归档和恢复遵守稳定身份及历史保留规则，以便停止新业务时仍能追溯旧运行。
23. 作为使用者，我希望弹层内成功和失败反馈可见，以便知道提交是否生效。
24. 作为使用者，我希望打开和关闭抽屉、按 Esc 及重新打开时行为一致，以便不会被多层弹窗或失效状态困住。
25. 作为 Windows 使用者，我希望在常用缩放、窗口尺寸和长名称条件下仍能完成关键操作，以便不受布局遮挡影响。
26. 作为键盘或高对比度使用者，我希望焦点和关键状态可辨认、操作可达，以便完成相同业务流程。
27. 作为部署者，我希望在另一含空格目录完成初始化与启停，以便安装不依赖开发者原目录。
28. 作为部署者，我希望端口冲突明确报错且停止操作只影响本实例，以便不误伤其他程序。
29. 作为维护者，我希望旧库升级后历史报告、身份和证据保持可用，以便安全更新平台。
30. 作为维护者，我希望备份恢复流程经过隔离环境验证，以便必要时能恢复可用版本与数据。
31. 作为交付负责人，我希望拿到支持范围、版本身份、验证结果和已知限制，以便判断是否具备交付条件。
32. 作为交付负责人，我希望真实运行受阻和远程 CI 未执行被明确列出，以便不会得到虚假的全通过结论。

## Implementation Decisions

1. 本规格是既有功能的验收与缺陷收口，不是新架构建设。默认不新增服务、依赖、数据库结构或公共接口；如范围内修复确实改变接口，须同步契约和消费方；数据库变化只追加迁移。
2. 按五个可独立交付阶段推进：状态校准、真实运行闭环、Windows 交互验收、部署升级验证、交付基线。设备受阻不影响交互、部署和文档工作推进。
3. 状态校准建立逐项证据映射，统一区分“已通过、已实现待验、未完成、受阻”。保留历史记录，不抹除原始失败。汇总与后续具体证据冲突时，以明确版本和条件的证据判断，不机械沿用旧汇总。
4. 状态校准同时核对实际分支、提交、工作区、构建身份和远端情况。无版本标签不等同于无法识别构建；不得继续沿用已被代码修复的旧描述。
5. 真实运行使用隔离测试项目与经授权的设备、可信套件和构建版本。覆盖 UI、性能、联动和调试中缺乏有效证据的路径，不将独立性能场景描述为执行了业务操作。
6. 遵守稳定身份决策：项目编码、应用所属项目、目标端及应用标识创建后固定；改名只改显示信息；归档可恢复并保留历史，不引入永久删除。
7. 保持运行状态与运行结论分离、缺失指标不写零、原始判定不被重分析覆盖、资源占用互斥及证据完整性等既有规则。
8. 交互验收优先覆盖统一项目上下文、报告深链接、弹层反馈、抽屉关闭及重新打开。遵循近期渐进式披露设计，不重新要求严格恢复旧原型的首屏布局。
9. 实际 Windows 验收记录系统版本、架构、浏览器、缩放与窗口条件。覆盖 100%/125% 缩放、窗口调整、长名称、键盘和鼠标操作、高对比度，以及适用的浅色/深色环境；不由此新增主题系统。
10. 部署验证在另一含空格目录和隔离数据库、产物目录进行，验证初始化、启动、停止、端口冲突、旧库升级和备份恢复。不替换或清理用户当前业务数据。
11. 历史 runner 消失原因未定位，保留为观察项；已有残留录制处理不等于根因已解决。若本轮复现，再针对运行进程退出路径调查，禁止预先扩大为全面重构。
12. 只修复本规格验收暴露的相关缺陷；每次有意义的修改后验证受影响行为。外部服务不可用记录原因与影响，不将修复无关上游作为交付前提。
13. 最终交付包含验收矩阵、版本身份、部署升级恢复说明、支持范围和已知限制。任何必需验收仍待验或受阻时，结论为有明确缺口，不能标为整体通过。
14. 本次请求仅授权编写和本地发布规格，不授权执行规格中的设备操作、实现修复或发布动作。后续执行仍遵守已有数据、依赖与发布授权边界。

## Testing Decisions

1. 用户已确认：以现有浏览器业务流程和 Windows 部署流程为主要验收入口；后端接口及数据库测试仅补充页面难以验证的规则，已有有效证据直接复用。不新增测试框架。
2. 好的测试检查用户可观察的行为、结果和持久数据，不能以源码字符串匹配、构建成功或 DOM 存在代替实际交互和视觉验证。
3. 优先复用既有正式化行为测试、运行生命周期与资源租约测试、联动组件测试、原始判定和重分析测试、报告在线查看测试及前端行为测试。按变化影响面选择最小必要集合。
4. 正常路径覆盖首次使用到报告追溯，以及真实 UI、性能、联动、调试。失败和边界路径覆盖用例断言失败、条件缺失、取消、资源已占用、指标缺失、冲突上下文和归档后新业务拒绝；已有有效证据无需重做。
5. 项目上下文通过浏览器跨页、刷新、深链接和切换实际验证。稳定身份、归档守卫及直接接口绕过等规则，复用隔离数据库和接口行为测试补足。
6. 弹层内分别触发真实成功及失败反馈，确认提示可见；验证抽屉一次关闭、Esc 后重开与焦点行为。操作仅写隔离测试数据。
7. 视觉验收检查实际渲染和可操作性，保留关键状态截图及环境信息；缺少桌面会话或目标环境时标记待验并注明原因，不以类型检查代替。
8. 部署验证检查另一目录的完整启停及健康响应、端口占用失败、实例停止范围。升级恢复前后对照稳定身份、历史运行、报告及证据完整性；失败后恢复隔离备份并记录结果。
9. 每项证据记录用户故事编号、版本、环境、操作、预期、实际、证据位置及状态。复用证据另注明原验证时间和继续适用的依据；部分路径通过不得覆盖尚未验证的部分。
10. 代码、配置或验证条件改变，或发现具体未覆盖验收条件时才补测。依赖未变化时，不为重复确认而重跑全量；需要的契约、类型、构建和隔离数据库检查随实际修改执行。
11. 本地等价检查不能标为远程 CI 通过。远程 CI 未具备条件时独立记录，不伪造发布结果，也不阻塞可以独立完成的本地验收。

## Out of Scope

- 重新实施已有开发阶段、重写整体架构或再次改造整站视觉。
- 登录、多租户、细粒度权限、跨机器调度、iOS/Web 真实执行、对象存储和实时性能推送。
- 尚未由实际使用反馈证明必要的新引导功能或报告功能扩展。
- 未复现的历史异常的全面调查、理论竞态加固或无关上游服务修复。
- 修改 vendor 源码、静默更换依赖版本或自动安装依赖。
- 未经授权操作共享真实数据、清理用户文件、安装应用或调整设备设置。
- 自动提交、推送、创建发布、打标签或配置远端；这些动作需要独立授权。
