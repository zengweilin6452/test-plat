# 01: 校准状态与验收证据

**What to build:** 让维护者准确区分已有有效证据、仍需验收的功能和环境阻塞，形成可以持续更新的验收基线。

**Blocked by:** None (can start immediately)

**Status:** resolved

**规格依据：** TestDock 首个可交付版本收口规格；用户故事 1、2、3、31、32。

## Acceptance criteria

- [x] 读取当前分支、提交、工作区变化、构建身份与远端状态；记录实际基线，不覆盖其他工作的修改。
- [x] 将规格全部 32 条用户故事映射到本组工单和证据，区分已通过、已实现待验、未完成、受阻。
- [x] 逐项判断历史证据的版本、代码、配置和环境是否仍适用；可复用的记录时间与依据，不重复执行有效验证。
- [x] 核对状态汇总与后续具体记录中的冲突，保留历史事实及失败，指出被后续实现或证据取代的旧描述。
- [x] 记录真机、可信套件、桌面会话与部署环境的缺口和解除条件；本地检查与远程 CI 结论分开。
- [x] 给出可直接执行的剩余验收清单，不修改或关闭父规格，不以汇总完成代替业务验收通过。

## 执行与证据边界

- 本票负责完整业务路径及其暴露的范围内缺陷，优先复用已有实现、测试入口和有效证据，不增加未经约定的架构或依赖。
- 每次有意义的修改后检查实际受影响行为。证据注明提交与工作区变化、环境和操作；涉及未提交代码时不能只以 HEAD 标识版本。
- 只在隔离数据和经授权的资源上执行。设备、可信套件、桌面会话等是环境前提，缺失时记录影响与解除条件；不伪造通过，不阻塞其他独立工作。
- 同设备验收需要错峰，共享设备不构成新的工单依赖。其他工单尚未完成不妨碍复核本票自身证据。
- 本组工单的发布不代表执行授权；后续实施遵守规格的数据、设备、依赖与发布边界。不得覆盖其他工作的修改，不修改或关闭父规格。
