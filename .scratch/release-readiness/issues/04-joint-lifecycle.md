# 04: 联动运行与资源释放

**What to build:** 让 UI 执行与性能采集在同一次资源独占期间正确联动，并在结束或异常后释放资源。

**Blocked by:** None (can start immediately)

**Status:** resolved

**规格依据：** TestDock 首个可交付版本收口规格；用户故事 12、13、14、17。

## Acceptance criteria

- [x] 真实联动运行的采集窗口覆盖 UI 执行，分别保留 UI 和性能组件结果及证据。
- [x] 正常完成、组件失败、取消和执行错误遵守既有结果收敛规则，不把异常伪装成正常完成的通过结果。
- [x] 同设备的运行和调试保持互斥；被占用时按现有规则排队或拒绝并解释原因。
- [x] 运行结束或取消后资源可再次使用；检查必要的进程与占用收尾，不影响其他实例。
- [x] 复用有效的生命周期、租约和组件矩阵证据，只补充缺失的真实联动路径；记录时间窗口和运行身份。
- [x] 历史 runner 消失保留为观察项；只有本轮复现才调查退出路径，不将残留录制处理写成根因已解决。

## 执行与证据边界

- 本票负责完整业务路径及其暴露的范围内缺陷，优先复用已有实现、测试入口和有效证据，不增加未经约定的架构或依赖。
- 每次有意义的修改后检查实际受影响行为。证据注明提交与工作区变化、环境和操作；涉及未提交代码时不能只以 HEAD 标识版本。
