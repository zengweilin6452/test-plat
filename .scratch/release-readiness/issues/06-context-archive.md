# 06: 项目上下文与归档恢复

**What to build:** 让多项目使用者跨页操作、刷新和归档恢复时始终作用于正确测试对象，并保留历史追溯。

**Blocked by:** None (can start immediately)

**Status:** resolved

**规格依据：** TestDock 首个可交付版本收口规格；用户故事 20、21、22。

## Acceptance criteria

- [x] 浏览器中验证项目切换、跨页导航、刷新及深链接的范围一致；切换后清理不兼容的表单选择，不显示旧项目请求结果。
- [x] 双项目同名应用可明确区分，冲突 URL 按既有规则拒绝或提示，不静默操作错误对象。
- [x] 项目编码与应用所属项目、目标端、标识保持固定；显示名称修改不改变历史身份。
- [x] 归档阻止新业务，活动运行或调试占用时按既有规则拒绝；接口直接请求不能绕过服务端守卫。
- [x] 恢复使用原身份；父项目恢复不意外恢复原本单独归档的应用，历史运行和报告仍可访问。
- [x] 以浏览器行为为主要证据，隔离接口及数据库测试补足守卫和持久规则；记录相关缺陷修复及定向复验。

## 执行与证据边界

- 本票负责完整业务路径及其暴露的范围内缺陷，优先复用已有实现、测试入口和有效证据，不增加未经约定的架构或依赖。
- 每次有意义的修改后检查实际受影响行为。证据注明提交与工作区变化、环境和操作；涉及未提交代码时不能只以 HEAD 标识版本。
- 只在隔离数据和经授权的资源上执行。设备、可信套件、桌面会话等是环境前提，缺失时记录影响与解除条件；不伪造通过，不阻塞其他独立工作。
- 同设备验收需要错峰，共享设备不构成新的工单依赖。其他工单尚未完成不妨碍复核本票自身证据。
- 本组工单的发布不代表执行授权；后续实施遵守规格的数据、设备、依赖与发布边界。不得覆盖其他工作的修改，不修改或关闭父规格。
