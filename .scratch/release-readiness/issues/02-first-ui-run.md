# 02: 首次使用到 UI 运行与报告

**What to build:** 让首次使用者在隔离环境中从建立工作空间与测试对象走到真实 UI 运行，并能查看结论和失败证据。

**Blocked by:** None (can start immediately)

**Status:** resolved

**规格依据：** TestDock 首个可交付版本收口规格；用户故事 4、5、6、7、8、9、17、18。

## Acceptance criteria

- [x] 正式初始化不产生演示业务数据；通过页面设置工作空间、创建项目和登记 Android 应用。
- [x] 登记可追溯的构建版本和可信套件版本，创建任务修订并完成配置就绪验证；来源与执行均对应固定代码快照。
- [x] 在经授权的真机上完成成功用例及故意断言失败用例，区分运行状态、运行结论与执行错误。
- [x] 从报告定位任务修订、构建版本、套件版本、执行资源及证据产物；在线查看、相关图表和证据访问符合实际内容。
- [x] 缺少可信来源、构建或设备条件时给出真实原因，不伪造执行，不将未执行记录为通过。
- [x] 记录版本、设备、运行编号、操作及证据；优先复用仍有效的历史结果，仅补齐缺失或受变化影响的路径。

## 执行与证据边界

- 本票负责完整业务路径及其暴露的范围内缺陷，优先复用已有实现、测试入口和有效证据，不增加未经约定的架构或依赖。
- 每次有意义的修改后检查实际受影响行为。证据注明提交与工作区变化、环境和操作；涉及未提交代码时不能只以 HEAD 标识版本。
- 只在隔离数据和经授权的资源上执行。设备、可信套件、桌面会话等是环境前提，缺失时记录影响与解除条件；不伪造通过，不阻塞其他独立工作。
- 同设备验收需要错峰，共享设备不构成新的工单依赖。其他工单尚未完成不妨碍复核本票自身证据。
- 本组工单的发布不代表执行授权；后续实施遵守规格的数据、设备、依赖与发布边界。不得覆盖其他工作的修改，不修改或关闭父规格。
