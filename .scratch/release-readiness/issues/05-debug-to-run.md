# 05: 设备调试到再次运行

**What to build:** 让测试人员完成设备调试，结束会话后可以立即使用同一设备开展下一次运行。

**Blocked by:** None (can start immediately)

**Status:** resolved

**规格依据：** TestDock 首个可交付版本收口规格；用户故事 13、15、16。

## Acceptance criteria

- [x] 实际浏览器中验证设备预览可用、冻结快照不会随实时画面变化、定位操作对应正确图像与节点信息。
- [x] 运行占用设备时无法另开冲突调试会话；提示可辨认占用原因。
- [x] 结束调试后会话及资源占用按既有规则释放，同设备可进入下一次真实运行。
- [x] 关闭失败或设备不可用时显示真实反馈，不静默宣称成功释放。
- [x] 复用已有冻结画面与调试真机证据，核对当前代码与条件，避免无变化的重复实测。
- [x] 记录设备、版本、会话与后续运行身份，附关键交互和收尾证据。

## 执行与证据边界

- 本票负责完整业务路径及其暴露的范围内缺陷，优先复用已有实现、测试入口和有效证据，不增加未经约定的架构或依赖。
- 每次有意义的修改后检查实际受影响行为。证据注明提交与工作区变化、环境和操作；涉及未提交代码时不能只以 HEAD 标识版本。
- 只在隔离数据和经授权的资源上执行。设备、可信套件、桌面会话等是环境前提，缺失时记录影响与解除条件；不伪造通过，不阻塞其他独立工作。
- 同设备验收需要错峰，共享设备不构成新的工单依赖。其他工单尚未完成不妨碍复核本票自身证据。
- 本组工单的发布不代表执行授权；后续实施遵守规格的数据、设备、依赖与发布边界。不得覆盖其他工作的修改，不修改或关闭父规格。
