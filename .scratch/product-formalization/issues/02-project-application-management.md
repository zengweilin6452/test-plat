# 02: 项目与应用创建、改名

**What to build:** 用户可以从页面创建项目和 Android 应用，修改显示名称，并用稳定身份继续访问既有测试记录。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-03、AC-09、AC-16。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 项目编码创建时去空白并转小写，接受 1–60 位小写字母、数字、短横线，首位为字母或数字；存量编码不自动改写。
- [ ] 项目和应用名称去空白并校验 1–60 字符；项目编码、应用所属项目、目标端及标识创建后不可修改。
- [ ] 项目编码全工作空间唯一；应用标识在项目和目标端内唯一，包含归档记录。重复创建返回可理解的冲突及查看原对象入口；归档恢复入口由 04 接通。
- [ ] 本轮只允许新建 Android 应用，包名沿用现有校验；历史 Web/iOS 记录保持可读，不提供虚假的执行入口。
- [ ] 改名保留 ID、外键、任务修订、运行快照及证据；历史页显示当前名称时标清含义，不伪造运行时名称。
- [ ] 从空库页面创建并重新读取成功；隔离存量库验证追加迁移、重复创建及非法身份修改，存量冲突只报告、不合并。

## 实施边界与验证

遵守稳定身份 ADR；身份填错应建立正确对象，不迁移历史归属。归档和恢复由 04 完成。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
