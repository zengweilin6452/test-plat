# 09: 旧演示数据预览与受控处理

**What to build:** 用户可以查看旧演示数据候选、关联记录和识别依据，逐项决定保留、改名或归档，真实业务与历史资产得到保护。

**Status:** resolved

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-10、AC-16。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 默认只预览，根据种子固定身份、原字段及关联关系识别，不仅按星河或 Demo 名称判断；已修改或信息不足时标为需人工判断。
- [ ] 预览列出稳定 ID、当前名称、匹配依据、关联数量、真实运行和活动占用，只有实际支持的操作才可选。
- [ ] 用户逐项确认后执行保留、改名或归档；执行前重新校验对象与占用，过期或无法确认的预览返回原因，不执行。
- [ ] 演示项目已承载真实测试时支持保留并改名；不搬移数据、不改身份、不重建历史记录；无安全归档语义的设备记录保留并说明。
- [ ] 重复执行稳定，不物理删除，不更改修订、原始判定、产物路径或哈希；成功后失效的页面选择有明确提示。
- [ ] 提供备份与恢复说明，在隔离旧库副本验证原始 seed、改名 seed、真实同名对象和执行期间状态变化；处理真实库须另有具体清单确认。

## 实施边界与验证

不能将实现此工具视为已获准清理共享数据；不依赖未来演示来源标记判断存量记录。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
