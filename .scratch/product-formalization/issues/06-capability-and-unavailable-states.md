# 06: 真实能力与不可用状态展示

**What to build:** 用户能区分平台不支持、设备未就绪、输入未配置和读取失败，看到的可执行能力与后端实际能力一致。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-12、AC-14。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 服务端提供最小能力摘要，前端能力标签、选择和执行入口使用同一来源；不建设插件系统。
- [ ] 平台支持和设备就绪分别展示，能力请求失败时不默认显示可执行；未支持平台不提供假执行。
- [ ] 缺少可信来源、设备或性能前置条件时分别显示真实原因及下一步；加载、空态、失败不混用。
- [ ] 盘点表单默认值和示例：版本、包名及设备示例不能自动提交，必要默认值注明单位和范围，缺失指标不补零。
- [ ] 删除本范围内“已有组件基础”等过时能力描述，保留可展开的错误码和请求 ID 供排障。
- [ ] 通过服务端能力响应和页面交互验证支持、未支持、读取失败及设备未就绪；保留测试夹具与明确标注的帮助示例。

## 实施边界与验证

不增加 Web/iOS 执行、不自动安装或修复设备，不因去硬编码将协议枚举和设计令牌改成配置。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
