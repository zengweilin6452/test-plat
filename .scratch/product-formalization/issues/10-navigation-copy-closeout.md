# 10: 正式导航、帮助与文案收口

**What to build:** 用户看到统一的正式产品导航和可执行的提示，帮助与开发者资料仍能通过新入口和旧链接访问。

**Blocked by:** 01: 工作空间设置与真实品牌信息；05: 全站数据与操作跟随当前项目；06: 真实能力与不可用状态展示

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-14。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 帮助和开发者入口承接接入说明、数据设计，旧路径兼容或重定向；不因导航调整破坏已有深链接。
- [ ] 清除剩余运行时固定业务名称、假身份、P1/P6/P2 将提供等研发阶段文案，业务提示说明真实结果及下一步。
- [ ] 表数量等动态描述由实际数据提供，读取失败如实呈现；关于页和帮助入口不重复制造品牌与版本定义。
- [ ] 逐项复核硬编码处理清单，记录保留协议/设计常量、帮助示例、测试夹具与历史参考的理由；不要求历史资料删除星河。
- [ ] 浏览器检查长名称、较窄窗口、100%/125% 缩放、键盘焦点及实际支持的主题/高对比度；检查提示、确认和错误状态。
- [ ] 以真实导航与交互验证完成，不以源码关键词消失作为唯一验收。

## 实施边界与验证

不添加主题系统或品牌自定义；部署说明由 11、初始化说明由 07 维护。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
