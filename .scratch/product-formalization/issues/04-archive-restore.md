# 04: 项目与应用归档、恢复

**What to build:** 用户能够预览归档影响并归档或恢复对象；平台保护进行中的活动和历史资产，在页面和直接接口调用下执行同一规则。

**Blocked by:** 02: 项目与应用创建、改名

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-04、AC-05、AC-06、AC-09。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 归档预览显示关联数量和影响；存在非终态运行、未关闭调试或相关资源占用时拒绝，并提供具体阻塞对象及查看入口，不自动取消活动。
- [ ] 项目检查整个项目；应用检查其相关运行和会话。无法归属应用但占用项目设备的会话保守阻止应用归档并解释原因。
- [ ] 项目归档后子应用不可开展新业务，但不改写各自归档标记；恢复项目不恢复此前单独归档的应用，父项目归档时不能恢复子应用。
- [ ] 归档范围禁止业务配置写入、构建/套件版本/基线登记、运行、重跑和调试；服务端各入口都执行校验，管理层仍允许改显示名和恢复。
- [ ] 归档与新运行提交使用一致的事务保护，普通并发下不能在归档成功后插入新运行；重复归档和恢复结果稳定。
- [ ] 正常业务选择排除归档对象，管理和历史查询可筛选归档；重复身份冲突能进入原对象的恢复操作。
- [ ] 历史运行、报告、证据和深链接保持可读，ID、快照、原始判定和哈希不变；隔离测试覆盖页面操作、直接接口绕过、父子状态及并发提交。

## 实施边界与验证

不提供永久删除；本票负责完整归档状态保护，不能只实现按钮和数据库标记。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
