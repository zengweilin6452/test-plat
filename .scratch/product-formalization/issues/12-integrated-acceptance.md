# 12: 正式化整体验收与升级验证

**What to build:** 形成可追溯的正式化验收结论，确认各独立功能组合后仍能在新环境和已有数据环境中正确使用。

**Blocked by:** 04: 项目与应用归档、恢复；08: 首次使用到第一次真实运行；09: 旧演示数据预览与受控处理；10: 正式导航、帮助与文案收口；11: 可迁移的 Windows 部署与启停

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-01、AC-02、AC-03、AC-04、AC-05、AC-06、AC-07、AC-08、AC-09、AC-10、AC-11、AC-12、AC-13、AC-14、AC-15、AC-16。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 逐项核对 spec 的 AC-01 至 AC-16，记录实现版本、环境、操作和证据；区分本次执行、复用历史、待验和受阻。
- [ ] 验证空库首次运行、双项目同名应用、切换与冲突 URL、归档恢复及直接接口绕过；归档状态和上下文组合后仍符合规则。
- [ ] 验证旧库升级、演示候选处理、历史报告和证据不变，以及正式/演示隔离；仅在隔离数据上执行验收操作。
- [ ] 按实际变更运行隔离数据库测试、前端行为测试、类型检查、构建和契约检查；不把源码字符串检查替代行为测试。
- [ ] Windows 浏览器检查窗口、缩放、长名称、焦点及错误反馈；完成页面到真机测试与报告追溯，无法执行时保留明确缺口。
- [ ] 核对每张工单的硬编码清单、追加迁移、配置示例、部署说明和旧数据处理说明完整且一致；不改写历史迁移。
- [ ] 发现本规格范围内组合缺陷时修复并复验；原有联动空异常、vendor 缓存和远程 CI 待办另列，不伪称本轮已解决。
- [ ] 输出逐项状态和剩余阻塞，不自动提交、推送、发布、安装依赖或清理用户数据。

## 实施边界与验证

本票负责集成验收及其暴露的范围内缺陷；各功能工单仍需先完成自身测试，不能把测试全部推迟到本票。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
