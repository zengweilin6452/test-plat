# 08: 首次使用到第一次真实运行

**What to build:** 新用户从干净正式环境进入引导，经工作空间、项目、应用、设备和测试输入登记，完成第一次真实运行并查看报告。

**Blocked by:** 01: 工作空间设置与真实品牌信息；05: 全站数据与操作跟随当前项目；06: 真实能力与不可用状态展示；07: 正式初始化与演示环境隔离

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-01、AC-12、AC-15。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 欢迎页按真实数据计算待办，提供设置工作空间、建立项目/应用、同步设备及登记输入入口；可跳过并随时返回。
- [ ] 本机执行节点通过现有同步机制或最小幂等登记建立，不依赖演示节点；从新项目设备页发现实际设备。
- [ ] 构建身份核对、可信来源/套件或性能场景登记、任务创建与运行复用已有流程，表单带正确项目和应用。
- [ ] 缺条件时给出准确下一步，不允许浏览器任意指定宿主源码路径，不自动安装应用或调整设备设置。
- [ ] 隔离环境通过浏览器完成新项目到报告/证据访问，不手改源码和数据库；记录设备、版本、运行 ID 和实际结果。
- [ ] 设备不可用时将真机验收标为待验/受阻并注明原因，模拟通过不能替代真机结果。

## 实施边界与验证

这是可用的首用流程，不以欢迎页本身作为完成标准；归档组合及全站验收由 12 汇总。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
