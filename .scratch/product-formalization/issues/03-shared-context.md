# 03: 统一项目与应用上下文

**What to build:** 用户从统一选择入口切换项目和应用，页面刷新、导航、历史链接和上次选择都不会把用户带到错误对象。

**Blocked by:** 02: 项目与应用创建、改名

**Status:** ready-for-agent

**规格依据：** TestDock 正式化改造规格（2026-11-03）；AC-08。遵守已确认的单工作空间边界及稳定身份、可恢复归档决策。

## Acceptance criteria

- [ ] 提供共享的有效上下文解析入口，校验项目、应用及目标端的关系；各页面不再独立猜测默认项目。
- [ ] 明确 URL 选择优先，其次是经过实际对象校验的缓存，最后未选择；显式“全部项目”不能被缓存覆盖。
- [ ] 仅提供应用参数时从实际应用解析项目；项目与应用冲突、对象失效时提示并给出修正入口，不静默切换到其他对象。
- [ ] 切换项目清理不兼容的应用选择；URL、本地偏好和共享状态一致，缓存不充当业务数据。
- [ ] 上下文入口和页面外壳可实际演示选择、跨页及刷新；业务列表与表单接入由 05 完成，旧入口过渡期间保持可用。
- [ ] 深链接按对象身份解析，不受其他项目缓存干扰；模拟无效缓存、仅应用参数、冲突参数和显式全部状态验证实际行为。

## 实施边界与验证

采用兼容式接入，不先删除尚未迁移的旧调用；03 提供可用入口，05 完成全部业务消费者迁移。

实施前补齐本范围的硬编码清单，说明实际用途、目标来源、处理方式及对应验收编号。涉及存储时只追加迁移；涉及 API 时同步契约、前端类型和相关文档。每项通过须有可观察的行为或持久结果证据，不只检查内部实现。不得覆盖用户已有改动或清理未授权数据。
