# TestDock 正式化改造规格

Status: ready-for-agent

- 日期：2026-11-03
- 代码盘点基线：`7511fc0`，`integration/first-release-closure`。
- 决策依据：用户要求全面清理硬编码和演示痕迹，并确认本规格中的四项推荐决策。
- 本次交付为规格及领域文档；不表示产品实现或验收已经完成。
- 术语：[GLOSSARY](../../GLOSSARY.md)；身份决策：[ADR-0001](../../docs/adr/0001-stable-project-application-identity.md)。

## 1. 问题与目标

当前平台已有真实测试能力，但产品外壳、首次使用和部署仍依赖原型约定。侧栏、面包屑及上下文条写死“星河”，身份栏写死“测试工程组”，阶段标签同时出现 P1/P6；安装说明要求导入演示业务数据，项目与应用只有查询接口，空数据库不能通过页面完成首次建立测试对象。

目标：新用户在 Windows 同机 Android 环境中，不修改源码或直接修改数据库，即可配置工作空间、建立真实项目和应用，并通过既有登记、设备和运行流程完成第一次测试。换项目、改名、归档或迁移安装目录后，显示内容和业务操作仍一致，历史结果保持可追溯。

“清理硬编码”覆盖产品页面、业务默认值、初始化、运行配置、脚本和用户文档；不是将所有字符串变成可配置项。协议枚举、状态映射、设计令牌和有依据的默认值可以保留。测试夹具、历史验收和原型参考文件可以保留示例，不能作为正式数据回退来源。

## 2. 已确认决策与范围

1. 保留 TestDock 品牌；单工作空间、本机使用模式，无登录。本轮不引入租户、账号、角色权限或多工作空间。
2. 项目与应用支持创建、编辑显示名称、归档、恢复。身份字段创建后固定；无永久删除入口。有排队、执行或调试占用时阻止归档并说明阻塞对象。
3. 默认安装不灌演示数据。旧数据先识别、预览，由用户选择保留、改名或归档；不能按名称批量删除。
4. 允许调整旧原型信息结构，保留视觉风格；增加设置及首次使用引导，将接入说明与数据设计放到帮助或开发者入口。

本规格明确扩展旧首期规格中“应用 CRUD 不在范围”的限制，仅增加本节定义的管理能力，不包含 APK 上传、安装和业务身份迁移。原型“九项导航顺序不可改”等实现注释在本范围内由本规格取代。

## 4. 工作空间、品牌与系统信息

- 工作空间仅有一个名称设置，默认显示“默认工作空间”，允许在设置页修改并持久化到服务端；不为本期建立租户关系或工作空间切换器。
- 工作空间名称和项目/应用显示名称均去除首尾空白，长度 1–60 字符；空值及超长值由前后端明确拒绝，按文本渲染。
- TestDock 名称、Logo、浏览器标题由统一品牌定义提供，本期不增加品牌编辑界面。
- 页面第一次加载显示加载态；设置读取失败显示错误和重试，不展示伪造的已配置名称。保存失败保留输入但不显示成功。
- 侧栏和面包屑共享工作空间来源。业务上下文条显示当前项目和应用，未选择时明确显示“全部项目”或“未选择应用”。
- 删除虚构用户信息，不把“本机模式”当作登录或权限保证。继续保持既有回环绑定和控制面保护。
- 关于页显示真实产品版本；提交标识只在构建能提供时展示，否则说明不可用，不编造“交付就绪”状态。改名后当前页面、切页和刷新均使用新值。

## 5. 项目与应用管理

### 5.1 身份与唯一性

- 项目：稳定 ID、不可修改的编码、可修改的名称、归档状态。编码创建时去空白并统一小写，接受 1–60 位小写字母、数字、短横线，首位为字母或数字；既有编码不批量改写。
- 应用：稳定 ID、所属项目、目标端、应用标识、名称、归档状态。所属项目、目标端和标识不可修改；Android 标识沿用当前包名校验。
- 新建项目编码在全工作空间唯一；应用在同一项目及目标端下的标识唯一，归档记录仍占用唯一键。名称只作展示，不作为关联主键。
- 同身份重复创建返回冲突并提示查看或恢复原对象；身份填错时建立正确身份的对象，不迁移历史引用。已有数据库约束若不符合，使用追加迁移调整，先报告存量冲突，不自动合并。
- 本轮新应用登记仅开放已有执行能力的 Android；历史 iOS/Web 数据保留可读，未支持能力明确提示，不能创建可执行任务。

### 5.2 归档与恢复

- 归档前展示影响范围及关联记录数量；存在非终态运行或尚未关闭的相关调试会话时拒绝，并提供跳转，不暗中取消运行或关闭会话。
- 项目归档检查整个项目的运行、调试及资源占用；应用归档检查其运行和能关联到该应用的会话。若调试会话无法归属应用而占用项目设备，保守阻止应用归档并说明具体会话。
- 归档校验和新业务写入必须在服务端保持一致：归档成功后不得再插入该范围的新运行；复用现有事务与锁机制，覆盖提交运行与归档相遇的普通并发场景。
- 归档项目下的应用均视为不可开展新业务，不批量改变子应用自己的归档标记。项目恢复后，单独归档的应用仍归档；父项目未恢复时拒绝单独恢复子应用。
- 归档对象仍可查看详情、历史运行、报告和证据。禁止新增或修改业务配置、登记新构建/套件版本/基线、启动或重跑测试和调试；管理层只允许改显示名及恢复。
- 正常选择器默认排除归档对象，管理列表和历史查询提供明确的归档筛选。重复归档/恢复应返回稳定结果，不重复产生业务影响。
- 改名不改写既有任务修订、运行配置、原始判定或证据。历史页面可显示对象当前名称，但明确标为当前名称，追溯依赖稳定 ID 和原始快照；不得将新名称伪装成运行时的原始记录。

## 6. 全站上下文一致性

- 工作空间 → 项目 → 应用 → 目标端的关系由一个共享解析入口校验；页面不能独立猜测默认项目。
- URL 明确选择优先，其次是经过服务端对象有效性校验的上次选择，最后是未选择。增加显式“全部项目”状态，避免清空 URL 后又恢复旧缓存。
- 无效 URL 不静默落到另一个项目；显示对象不存在、已归档或关联不匹配及修正入口。仅有 app 参数时可根据实际应用解析项目；project 与 app 冲突时拒绝混用。
- 项目切换清除不兼容的应用、设备、构建、套件及待提交表单选择，并同步查询缓存键、URL 与本地偏好。缓存只保存选择，不充当业务数据来源。
- 工作台、任务、报告和设备支持真实项目范围，“全部项目”明确展示跨项目汇总；UI/性能页按明确应用开展写操作。
- 所有查询与提交都验证 project/application/build/suite/resource 等关联关系。只改页面标签或前端筛选不算完成。
- 详情深链接保留被查看对象身份，不因最近一次选择属于其他项目而显示错误数据；历史归档对象仍可通过只读详情访问。

## 7. 首次使用与正式初始化

1. 安装依赖、配置连接和目录、执行迁移；仅建立必要系统设置，不自动生成业务项目及伪设备。
2. 首次进入显示欢迎与真实待办：设置工作空间名称 → 创建项目 → 登记 Android 应用。
3. 从项目设备页同步真实设备。执行节点的必要登记由现有同步机制完成或补齐幂等的本机登记，不能依赖演示脚本中的节点。
4. 按已有能力登记构建并核对身份、选择可信套件来源或登记性能场景，再创建任务运行。
5. 没有来源、设备或性能前置条件时，显示原因和对应配置说明；引导可跳过，之后仍可返回，完成状态从真实数据和检查结果计算。

可信源码路径仍由宿主配置，不新增浏览器任意宿主路径输入。就绪检查只检查现有边界，不自动安装应用或修改设备设置。设备和版本不得默认选取演示标识；指标缺失、计数读取失败分别展示未判定或读取失败，不补零冒充成功。

演示模式必须显式使用独立数据库和产物目录，页面持续显示“演示环境”。假执行仅用于测试或显式演示环境，正式启动若检测到假执行配置应拒绝启动并提示纠正，不能生成看似真实的通过结果。

## 8. 旧演示数据处理

- 默认只预览，不自动执行改名或归档。根据 seed 的固定 ID、原始字段及关联关系识别候选项，不根据“星河”“Demo”等名称单独判定。
- 预览列出稳定 ID、当前名称、匹配依据、实际关联数量、是否存在真实运行及活动占用。信息不足或已被用户修改时标为“需人工判断”。
- 用户逐项选择保留、改名、归档；历史演示项目已承载真实数据时允许直接保留并改名，禁止擅自重建或迁移这些记录。
- 执行前重新校验选择对象和活动占用。过期预览或无法确认的对象不执行，返回原因；重复执行不重复改写历史。
- 本轮不实现物理删除。演示子记录按对象类型给出可行操作；没有安全归档语义的设备等记录保留并明确说明，不伪造新的生命周期状态。
- 迁移及归档保留原始 ID、外键、修订、产物路径和哈希。实施前备份，先在隔离的存量数据副本验证，再对用户确认的清单执行。
- 新增来源标记仅用于以后显式导入的数据；不能倒填“已确认演示”去掩盖旧数据识别不确定性。正式启动和升级均不得重新灌入演示数据。

## 9. 文案、能力和部署配置

- 业务文案解释结果和下一步，不展示研发阶段、原型行号、接口尚待 P2 等说明。技术错误码和请求 ID 可放详细信息；保留排障能力。
- 帮助与开发者入口保留接入说明、数据设计和原有深链接；旧路径兼容或重定向。表数量等动态描述读取真实数据，不继续写死“24 张表”。
- 目标端及操作能力由服务端统一提供最小能力摘要，复用现有元信息能力，不引入插件平台。能力可用与设备就绪分别表达；能力读取失败不显示可执行。
- 页面示例清楚标为“例如”，表单真实值来自选择、输入或可信检测；示例版本号、包名和设备标识不能自动提交。
- 数据库、产物目录、运行时目录、Python、ADB、可信来源沿用现有配置机制。路径从配置或安装目录解析，不依赖开发者个人目录；不得将凭证、令牌、连接串或宿主敏感路径放进公开前端配置。
- 启停脚本、前端代理和健康检查使用一致的端口配置；默认仍可为 8000/5173，必须支持明确覆盖。端口占用时明确失败，不以陌生进程返回 200 判断本平台已经就绪。
- 正式使用路径与开发者 vendor 同步路径分开：已有 vendor 快照可直接使用；同步时通过显式来源配置，不依赖某人的 D 盘仓库。保持 vendor 源码只读纪律。
- 提供不含秘密的配置示例及 Windows 操作说明。README 的默认路径为正式初始化，演示安装作为单独章节，不增加未经批准的依赖或外部来源。

## 10. 实现边界与交付顺序

| 阶段 | 交付 | 依赖 |
| --- | --- | --- |
| A | 硬编码清单、工作空间设置、身份与归档字段及 API 契约 | 本规格 |
| B | 项目/应用创建编辑归档恢复，后端状态和归属校验 | A |
| C | 全站上下文、真实名称、筛选及深链接统一 | A、B |
| D | 空库引导、真实节点/设备接入、正式与演示初始化隔离 | B、C |
| E | 旧数据预览处理、文案导航、能力摘要、部署配置 | B、C；部署配置可独立推进 |
| F | 新库、旧库、双项目、换目录及页面到真机验收 | A–E |

沿用现有 FastAPI、PostgreSQL、React 及领域服务；最小扩展工作空间设置和项目/应用管理接口。只追加迁移，不修改历史迁移；修改 API 后同步 OpenAPI、前端类型、数据设计文档和相关测试。旧只读接口增加字段保持兼容，不以大规模重构作为前提。

实施时将本表拆为独立工单及依赖，规格不预先虚构开发完成时间。审查中剩余的联动空异常漏判、vendor 缓存校验、远程 CI 实跑属于既有收尾问题，单独跟踪，不因本规格写成已解决。

## 11. 验收标准

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 | 新库迁移和正式启动，不运行 seed | 无演示业务记录，无假设备/指标；欢迎页可建立真实项目和应用 |
| AC-02 | 修改工作空间名称并刷新、切页 | 侧栏和面包屑一致；保存失败不假成功；TestDock 品牌独立 |
| AC-03 | 创建、改名、重复创建及非法输入 | 名称校验生效；身份不可改；唯一性冲突可理解且不会重复创建 |
| AC-04 | 归档含排队/运行/调试占用的对象 | 服务端拒绝并给出具体阻塞；不取消现有活动 |
| AC-05 | 归档空闲对象、恢复父项目和子应用 | 禁止新业务，历史可读；父项目恢复不复活单独归档应用；重复操作稳定 |
| AC-06 | 绕过页面直接提交归档或跨项目对象 | 服务端拒绝，包括任务、运行、重跑、套件/构建登记、调试等入口 |
| AC-07 | 两个项目有同名应用及不同设备 | 页面标题、计数、列表、请求参数和最终持久记录均属于所选范围 |
| AC-08 | 刷新、跨页、显式全部、失效缓存及冲突 URL | 不回落到错误对象；应用可解析项目；冲突明确提示；旧详情可打开 |
| AC-09 | 改名/归档前后读取同一历史运行 | ID、修订快照、原始结论、证据路径及摘要不变，当前名和历史事实不混淆 |
| AC-10 | 旧库含原始 seed、已改名 seed、真实同名项目 | 预览正确区分候选与不确定记录；无按名称删除，无自动清理，执行后真实资产保留 |
| AC-11 | 显式演示安装与正式安装 | 数据/产物隔离；演示标识持续可见；正式环境拒绝假执行配置 |
| AC-12 | 来源未配置、无设备、未支持平台、接口失败 | 分别显示真实原因和可行下一步，不伪造空态、可用或成功 |
| AC-13 | 新目录含空格、覆盖端口和解释器路径 | 启动、代理、健康检查和停止一致，不读取原开发者路径，不误认其他服务 |
| AC-14 | 全站文案与导航检查 | 无运行时写死的星河、假团队和 P1/P6；无示例值自动提交；旧帮助深链接可达 |
| AC-15 | 从页面建立新项目到真机结果 | 不改源码/数据库；能登记输入、同步设备、创建运行、查看报告及证据 |
| AC-16 | 升级已有数据库并再次启动 | 不灌 seed，不改旧身份，不丢历史；迁移可重复部署且具有备份恢复说明 |

检查顺序：服务端隔离数据库行为测试 → 前端上下文及表单行为测试 → 类型检查/构建/契约校验 → Windows 浏览器真实页面流程。不能仅通过搜索源码中的函数名和文案就判定交互通过。

视觉检查覆盖常用桌面窗口、较窄窗口、100%/125% 缩放、长中文名称、键盘操作及焦点；检查实际支持的主题和高对比度可读性，不新增主题系统。创建、归档确认和错误反馈必须可用。

真机使用已有明确授权及隔离测试数据，保留设备、版本、环境、操作、运行 ID 和结果证据。设备不可用或尚无远程 CI 时记录未执行范围，不能用历史结果或模拟测试冒充本次通过；未变化的有效证据可明确引用。
