## 1. 目标与约束

用户能够在浏览器选择应用及固定测试输入，创建并验证任务，分配设备、发起真实执行、跟踪或取消运行，查看可追溯的结果和证据。性能运行可以分析并追加试算；调试支持原生节点与图像模板定位，冻结图像、节点、框选坐标和模板版本具有一致来源，模板可跨会话复用并被任务固定引用。

首期既有边界：Android 真执行；iOS/Web 配置草稿；单工作空间、同机执行；设备独占；原始判定不可覆盖；缺失指标不补零；不修改 vendor 源码。应用 CRUD、包上传、自动安装、多机调度、登录权限系统和实时性能采集曲线不因本规格自动加入范围。

已知已有能力应继续使用：套件与用例读取、设备同步和项目过滤、调试预览与模板匹配、报告读取与产物下载、scope 持久化、schema 的表/分组/泳道/流程数据。

### 3.1 证据状态

2026-10-28 的只读核对：14 条前端测试通过；真实 schema 数据与源码在 ES2022 目标下内存渲染，24 表全部落入“未分组”；真实结论文案函数将 performance/not_tested 固定成样本不足。

2026-10-29 补充源码复核：任务请求接受可选 build_id/suite_version_id；任务验证要求绑定；服务校验构建来自 app_builds 且属于同项目同应用；没有构建列表/登记路由。运行展示编号来自全库 row_number；health 只返回存活状态、版本与数据库目标。

以上是静态与内存证据。本规格编写时没有运行浏览器、后端、真机或数据库写入验收，也没有重跑 14 条测试。模板错位、报告字段在真实数据中的完整性及 joint 执行仍待专项验证。

原型在本轮新增了设备调试中的图像模板交互，已按 §3.2 摘要核对并对齐到 §6.9：

- 调试页签提供“原生节点 / 图像模板”定位方式切换，图像流程复用同一冻结快照，不另起设备访问。
- 冻结后可拖动框选，或用 X/Y/宽度/高度坐标输入；单位为设备像素，选区至少 4×4 且必须落在画面内，越界拒绝并提示；区域预览与框选共用同一内屏坐标映射。
- 保存模板版本时记录逻辑名、匹配阈值、来源设备与尺寸、快照标识和选区；同名保存追加新版本，旧版本保留。切换到来源尺寸不兼容的模板时清除旧选区并要求重新框选。
- 阈值限定 0.10–1.00，无效值阻止保存与验证；“重新匹配”会采集新快照、显示快照标识、分数、阈值和匹配结果，失败不伪造成功。
- IMAGE 表达式按逻辑名生成；查看历史版本不锁定版本，正式执行以固定清单为准。

原型明确标注阈值、分数、匹配结果和模板图片为本地模拟，未调用真实设备、模板服务或图像算法；这些模拟值和“复制表达式不锁版本”不能成为正式后端契约。目标契约见 §6.9，真实裁剪、匹配与版本锁定列入 §12 技术门槛。未修改或回退原型文件；正式视觉验收仍以 §3.2 摘要版本为准。

| INV-01 | 任务是可重复执行的定义；运行绑定确定修订。编辑产生新修订，不能改变已有运行的执行输入 |
| INV-02 | 配置就绪、设备在线、资源空闲、设备就绪分别展示；任一状态不能代替其他状态 |

| INV-04 | 缺失指标 value=null 且说明原因；真实零值与缺失分开；样本数为 0 可以是真实观测数量 |
| INV-05 | 性能结论由后端判定；not_tested 显示真实原因，未知原因不得被映射成样本不足 |
| INV-06 | 一个资源同时只有一个活动持有者。占用只读视图仅允许读取已发布且获准查看的数据；禁止另起 debug 会话、额外采屏/树请求或注入输入；无共享数据时显示不可预览 |
| INV-07 | 冻结图像、节点树、节点坐标和模板裁剪指向同一快照。实时定位验证如采新快照，须在对应图像显示结果或明确切换来源 |
| INV-08 | 每个性能组件的原始判定唯一，后续策略变化或试算仅追加 reanalysis，不修改原始判定和历史报告 |
| INV-09 | 构建、套件版本、修订、资源档案属于正确项目/应用/目标端；服务端强制校验，不能只靠下拉过滤 |
| INV-10 | 稳定运行编号由服务端提供；过滤、分页、新建或历史数据变动不得重编号。UUID 始终是精确身份，展示编号不代替主键 |
| INV-11 | iOS/Web 可保存草稿，不伪装真执行或设备就绪；UI 不把规划态显示成环境故障 |
| INV-12 | 所有可用操作有真实行为；空态、加载、请求失败、部分缺失、过期和未检查分别呈现 |

## 6. 核心流程与接口契约

### 6.0 本轮细化的固定规则与事实

以下来自既有约束或已批准 D1–D14，不要求再次批准：

- 构建登记不能覆盖同应用下已有 build_key 的身份。相同身份的重复登记返回已有对象；相同 key、不同身份返回冲突并保留原记录。技术性幂等键不能把不同业务请求合并。
- 空库闭环指：项目和应用、宿主工具及可信测试来源已按部署准备，但没有构建/套件/版本记录；用户在浏览器完成最小登记到执行。不扩展为浏览器编写脚本、安装依赖或创建整个开发环境。
- 发现 pytest 用例会加载测试模块和 conftest，子进程不等于安全沙箱；受控来源须事先可信。路径越界、符号链接逃逸及来源替换不能绕过边界；不向浏览器回显凭据或完整宿主配置。
- 当前 source_commit 可默认成 local，manifest 只固定 nodeid/目录，执行仍读目录文件。它不足以证明实际代码未变化；已批准 D6 要求保留固定代码副本，而非仅增加一个版本标签。
- 现有统一 case_total>0 只适合当前 UI 清单，不应强加给声明式性能场景。已批准 D7/D8 要求带类型的 manifest 分别验证真实 UI 用例、性能场景和联动组合，不能为满足校验拼虚假用例。
- 资源页的设备检查属于主动设备访问，必须受设备互斥控制；busy 时返回占用冲突，不读取额外设备数据。正式租约类型与短检查如何兼容在技术设计中解决，不在此暗示已有 readiness 租约类型。
- 每次运行在取得独占后执行针对测试类型的检查；UI 不因缺少纯性能工具自动失败，performance/joint 必须检查对应采集工具。已显示的历史检查有时间/适用类型，不能作为永久通行证。
- 检查项至少区分通过、警告、失败、跳过/未知。是否阻断由该测试类型要求决定；采集降级项保留真实原因，不能用整页绿色覆盖细项未知。
- health 不进行设备主动检查；readiness 与 health 不混用。D9 已确定只检查不自愈，不能借“检查”按钮静默改变设备连接方式。
- D1 的视觉验收覆盖默认入口、页签顺序、卡片/列表结构、关键字段和动作，以及原型 tokens；动态数据和内容长度允许合理变化。技术验证方式可选现有可用浏览器工具，不强制以脚本存在本身判定验收通过。

新增源码依据（2026-10-29，只读）：app_builds 唯一键为 project/application/build_key；services/suites.py 的 source_commit 默认 local、manifest 保存 suite_root；integrations/discover.py 使用宿主 pytest collect-only；runner/spawn.py 不支持 joint 并回退 ui；vendor PerfKit.collect 是可包围 UI 动作的上下文；vendor Keeper.run 失败分支含 tcpip/connect 自愈。均未实际运行或触发设备访问。

### 6.1 固定输入 → 任务就绪

- 应用工作区展示当前应用和平台，通过浏览器登记/选择属于该应用的固定构建与套件版本；D2/D6 已批准受控来源及平台固定副本。
- POST /tasks 沿用实际请求形状：name、test_type、platform、application_id，及可选 project_id/build_id/suite_version_id/environment_id/config。不得将旧文档的顶层 module/perf/device 示例原样当作现有请求。
- 草稿允许缺项；页面需显示未绑定内容，提供 PATCH 补齐并遵守 lock_version。不能为过验证伪造构建记录或空用例。
- POST /tasks/{id}/validate 成功会追加 validated 修订，不修改原修订；页面必须采用响应中的最新 revision.id 和 lock_version。失败统一解析实际 task_not_ready 的 missing/invalid。运行前置校验的 readiness_incomplete 保留为不同语义，除非后续统一契约并迁移消费方。
- PATCH 是带 lock_version 的并发更新并追加草稿修订；已有运行绑定不阻止任务产生新修订。config 整份替换，不做深合并；省略可选绑定字段表示不变，本期不以 null 暗示清空。旧修订及其 readiness 均不回写。
- 配置补齐不等于设备就绪。不同测试类型按 §6.6 的有效清单验证；性能场景不得为通过验证而伪装 UI 用例。

### 6.2 发起、跟踪和取消运行

- 运行入口使用既有 POST /runs，显式提交 application_id、platform、task_id、revision_id、request_key；指定设备放 device.resource_id，自动分配则省略 device。测试类型、构建和套件从所选 validated 修订取得，服务端核对归属；不依赖“该应用最新修订”或“首个应用”的隐式选择。精确字段与兼容见 §9.1–§9.2。
- 同一次操作重试复用幂等键；成功后跳转具体 run。自动 validate 或自动 start 失败时保留已创建 task/run 身份，重试不得从头重复创建。
- 展示服务端 state、组件、真实 progress 与事件；无进度数据不伪造匀速或 0%。修订历史与执行时间线分开。
- WS snapshot 初始化，state/event 增量更新，finished 收敛并刷新列表/报告；断线降级读取真实状态，重连后去重，不重复执行操作。
- POST /runs/{id}/cancel 表示受理；收到终态后才显示已取消。完成与取消竞争服从服务端最终状态。
- 忙设备排队/拒绝遵守现有服务端能力，不通过第二个调试会话绕开独占。

### 6.3 报告、原始判定与重分析

- 报告列表在服务端按 completed 过滤，再排序分页；搜索和模块筛选作用于完整结果集合，不只作用于已截取的 200 条。
- 现有 /runs 接口只有 scope/state/limit；完整检索和分页按 §9.3 扩展，不能声称当前已有 cursor。errored/cancelled 的部分证据从运行详情访问，不混入完成报告列表。
- GET /runs/{id}/report 返回运行身份、修订、构建、应用、资源及运行时档案、组件结果、原始判定、阈值快照、原因与证据引用。字段缺失须标缺失；不能以设备 serial 冒充档案。
- GET /runs/{id}/report/export 是待实现的服务端导出；内容与报告快照一致，文件名稳定，不混入演示标记、凭据或宿主敏感路径。
- 报告抽屉提供证据分类查看/下载、重跑、性能分析跳转；重跑引用原输入并形成新运行，不修改原记录。
- 产物只有 available 才提供可执行下载；expired/missing 保留元数据并说明原因。状态变化造成下载失败时给可读提示。

### 6.4 性能与门禁

- 分析接口提供真实指标 summary、样本数、缺失原因、时间序列、基线值和可追溯上下文；序列来自真实采集数据，禁止用中位数拼曲线。
- 无历史序列时保留真实汇总，明确“无时序数据”；新性能验收数据必须能证明趋势来源。
- 运行的 original 和明确选择的 reanalysis 分开展示；不得默认用最新试算替代历史报告。
- 跨档案基线显示不可比原因，不能生成可比百分比或绿色通过暗示。
- 保存阈值与发起试算是明确操作；保存策略不改历史 original。外部 POST /runs/{id}/gate-evaluations 仅创建 reanalysis；内部首次判定另有显式语义入口，可以复用领域计算但不复用模糊 mode 决策。
- 无 original 的外部试算不能冒充 original；已批准 D14 允许符合条件的已完成历史运行显式 reanalysis，详见 §6.8。

### 6.5 构建身份与代码副本（D5/D6 已批准）

- 构建逻辑身份为项目、应用、build_key；version 是业务版本。来源提交、包摘要可为空，但有值时不得覆盖冲突身份；无包摘要不得写成“包内容已验证”。首次设备实测按已批准 D10，经用户明确确认后成为固定基准；确认前保留待核对状态，业务 version 与实测 versionName 冲突则拒绝确认。
- 任务可以保存绑定未核对构建的草稿；允许配置验证完成，但在设备执行前身份核对必须通过。配置就绪不依赖某台设备此刻在线，不能把人工确认步骤藏进自动验证。
- 每次运行在已取得独占的实际目标设备上复核包名、versionName、versionCode 等固定核对项，记录设备、时间、预期与观测。不能仅复用首次设备结果。
- 构建基准一旦固定不再从另一台设备静默更新；冲突提示修正安装或选择正确构建，不提供“忽略并视为已验证”。误登记走新构建号/修订处理，不覆盖历史引用。
- 代码来源先按预配置可信目录解析，再形成平台管理的版本副本；记录相对文件清单及内容摘要，控制本地依赖边界。发现与执行都在该版本副本基础上进行。
- 源码副本与运行输出分开；发现或执行需要写缓存/报告时使用临时运行目录，不改固定原件。执行前验证原件摘要，损坏或缺失即阻断；不得回退到可变来源目录。
- 更新目录触发显式发现/版本创建；浏览器刷新、重跑旧任务不能自动将 V1 改成 V2。旧版本只能报告执行环境差异，不能宣称代码固定就保证环境完全相同。
- 本次不实现自动清理或删除入口；有引用的副本保留。磁盘不足返回明确错误，不自动淘汰旧副本。未来清理须另定依赖与留存规则并取得删除授权。
- 旧 suite_version 只有 local 标记或原目录时，标记“未保留固定代码”；仍可查看历史，但新运行前须显式创建具备代码副本的新版本与任务修订，不追认旧运行使用了新代码。

### 6.6 按类型验证清单与只读检查（D7/D9 已批准）

| 类型 | 配置就绪的真实输入 | 设备执行前检查 |
| --- | --- | --- |
| ui | 非空 UI 用例清单、固定代码副本、构建、适用目标和环境 | 包及固定版本身份、连接与 UI 适配器所需服务；不强制纯性能工具 |
| performance | 单个明确版本的声明式场景，含目标应用、duration_s、实际支持的采集项；不是伪造 cases | 身份、连接、采集工具/无障碍真实绑定及所选指标依赖；不代为安装或设置 |
| joint | 固定 UI 清单及代码副本 + 固定性能采集配置；版本将两部分作为一个完整快照保留 | UI 与 performance 所需项的合并；任一阻断项不允许静默降为 ui |

- 清单采用明确类型与形状版本；可使用现有 manifest/config 存储，不由此要求新增实体表。解析器对各类型实施不同就绪规则，并校验套件与修订测试类型一致。
- 声明式场景不存在“发现 pytest”的必要；浏览器登记/发布固定版本即可。纯性能 duration_s 沿用 10–3600 秒整数要求，修改场景生成新版本。
- 手动设备检查与运行准备都不执行 tcpip/connect、安装和设置修改；覆盖平台直接路径与 vendor 内部的隐式 ensure_ready，不能仅绕开按钮中的一层调用。
- 若当前 vendor 入口不能满足该约束，须在平台适配层提供等效受控检查/拒绝能力；不修改 vendor，也不静默退回有自愈的默认路径。实现可行性须用替身命令记录和授权设备验证证明。
- 检查/身份读取在同一设备互斥约束下完成；手动读取后及时释放，正式运行重新检查。忙设备不等待期间偷偷探测。
- 可选指标不支持时说明降级；必需工具缺失、身份不可读、关键服务未知均阻断对应类型执行。只有真实已测样本才进入指标统计。

### 6.7 联动生命周期与收敛（D8/D11/D12 已批准）

准备完成后开始采集，再启动固定 UI 执行，最后停止采集并归档；一个 run 两个组件，共享同一资源独占，不并行启动第二个独占拥有者。适配实现必须验证平台租约与 vendor 锁兼容，不能让两个独立子任务互相抢锁。

以下为已批准 D11/D12 的固定语义：

- 独立性能的 duration_s 表示采集时长；joint 使用 ui_timeout_s 表示最长 UI 执行时间，不能把同一个字段解释成“UI 后补采至满时长”。默认 UI 上限 600 秒，允许 10–3600 秒；由任务修订固定。
- UI 上限从实际启动 UI 执行起计；独立的准备、停止与归档均有配置上限，页面与事件记录实际阶段，不伪装成 UI 步骤。采集开始/结束时间记录实际数据窗口，UI 核心活动窗另记边界。
- UI 按套件固定的策略继续用例，不因平台发现首个断言失败额外施加 fail-fast；用例断言失败属于 completed/failed，不等于 runner 故障。
- UI 正常结束即停止采集；不等待最小样本数、不在 UI 后补空闲样本。短窗口导致 not_tested 时保留原始原因。

| 场景 | 整体状态/结论 | 组件与证据 |
| --- | --- | --- |
| UI 正常完成，性能已正常收口且可判定 | completed；任一 failed → failed，否则任一 not_tested → not_tested，否则 passed | 分别保留 UI 与性能结果，不能只显示整体 |
| UI 有断言失败，性能正常完成或样本不足 | completed/failed | UI 失败证据和性能数据均保留；性能未判定原因继续可见 |
| UI 被正常跳过且没有有效执行 | completed/not_tested，除非另一组件已有确定 failed | 不把零执行当通过；完整指标原样保留 |
| 采集启动失败 | errored / outcome=null | 不启动 UI；UI 组件终结为 cancelled 并标注“前置采集失败未执行”，性能为 errored |
| UI 基础设施错误、采集中不可恢复错误、整体阶段超时 | errored / outcome=null | 停止另一活动组件，保留已完成组件结果及可取得的部分证据；未开始组件标 cancelled 并注明原因 |
| 用户取消被执行器确认并安全收口 | cancelled / outcome=null | 已完成组件不改写；活动/未开始组件按实际停止结果标 cancelled。部分数据不可冒充完整门禁结论 |
| 取消与完成/错误并发 | 首个通过原子终态迁移的已确认事实为准，不能后写覆盖 | 记录取消请求与完成/错误发生事实，不以按钮点击时间伪造终态 |
| 取消超时、无法确认进程/设备已停止，或 fencing 失效 | errored / outcome=null，标注收敛失败或失联原因 | 拒绝失效拥有者继续提交结果；必须阻止旧执行继续访问设备，未证明安全前不可把设备显示为空闲候选 |

取消不是正常完成，不为部分采集产生可冒充正常 original 的判定；已持久化的合法证据保持可查看。采集可靠收口但缺样本是 not_tested，采集本身失败是 errored，二者不能混同。清理/收口包含停止进程和释放租约；不包含未经授权删除文件。

### 6.8 原始判定冻结点与历史重分析（D13/D14 已批准）

- 在资源/档案已确定、设备检查通过、采集开始之前解析默认策略和同档案基线并保存执行快照；明确指定的版本直接校验，失效不自动换成最新。运行提交配置与执行解析快照分开记录，一经固定均不可重写。
- 提交时 UI 显示“默认策略/基线在开始执行前确定”；如用户要求某版本，允许显式选择固定版本。队列等待期间默认更新是预定语义，不能显示提交时预览为最终原始门禁。
- 默认没有同档案基线时记录“无可比基线”，不自动选择跨档案基线作默认；显式跨档案对比保持 not_tested/profile_mismatch。缺策略/基线不是启动采集的必备条件，仍记录真实数据和原始未判定。
- 新运行的原始判定只使用该快照。试算使用用户指定的策略/基线版本，记录新的 reanalysis，不能根据“最新”在同一请求重试时悄悄换版本。
- 允许 completed 历史运行缺 original 时显式试算，只使用可核实的已留存数据与档案；返回 mode=reanalysis 并持续显示 original 缺失。不能用这次规则补造历史原始结论。
- 非 completed、输入不可用或必要来源不可核实时拒绝试算并给缺项；跨档案等“数据存在但不可比”保留未判定语义。报表缺 original 时不以最新 reanalysis 自动兜底。

### 6.9 调试定位与图像模板（D4 已批准）

- 调试工作区保留“原生节点 / 图像模板”两种定位方式；右侧全高面板是 D1 已批准的布局例外，模式切换、冻结、框选、保存和验证等关键动作不能因布局例外省略。
- 只有已冻结、设备空闲且快照有效的画面可用于节点拾取、框选、保存模板和匹配验证。实时预览不能代替冻结画面；busy 设备只读预览，不新建调试会话、不额外采屏或注入输入。
- 每次采集生成唯一 snapshot_id，绑定设备、分辨率、采集时间、图像摘要；原生模式同时绑定节点树。切换设备或重新采集会清除旧选区和未保存输入，不能沿用上一张画面的坐标。

**框选与坐标**

- 拖动框选与坐标输入等价，坐标单位为设备像素，范围 0..width、0..height；存储值不随浏览器缩放、DPI 或面板尺寸变化。
- 选区至少 4×4 像素，且 x+w≤width、y+h≤height；越界、非整数或无效输入拒绝并给出可修复提示，不静默夹取或扩大选区。
- 区域预览与框选覆盖层使用同一内屏坐标映射；预览与结果不一致时以快照坐标为准并修正显示，不能用不同映射各算一套。

**模板版本与作用域**

- 逻辑名限定 ASCII 字母、数字及 `_ - / .`，长度不超过 80；同名默认返回冲突，用户显式确认“新增版本”后才追加，旧版本不可变，不能覆盖。
- 每个版本记录 logical、version、image_sha256、region、source_snapshot_id、来源设备与分辨率、默认阈值及创建信息。模板图片由服务端从保留快照裁剪生成并记录摘要，不接受浏览器上传图片；快照不可用或裁剪失败时拒绝，不生成空模板。
- 模板库属于项目/应用范围，跨调试会话可见并可被任务引用；当前“模板按调试会话隔离”的实现不满足该契约，需平台侧持久化模板与图片，vendor 仅承担裁剪/匹配能力。会话结束不得删除已保存版本；本期不提供删除或自动清理，有引用版本保留。

**阈值、匹配与表达式**

- 匹配阈值限定 0.10–1.00（步进 0.01）；无效值阻止保存和验证，不能以默认值静默替换。
- 重新匹配必须显式采集新快照，并记录 matched、score、threshold、snapshot_id、模板 version 与 image_sha256；界面显示结果对应的快照标识，旧结果不能叠到新画面上。
- 匹配失败显示 0 个区域、分数和阈值；真实匹配能力不可用或未执行时返回明确不可用状态，不能显示模拟成功或占位分数。
- IMAGE 表达式按逻辑名、阈值和可选 region 生成；查看历史版本或复制表达式是编辑期行为，不锁定版本。正式执行必须固定 template version_id、image_sha256、region 和 confidence 并写入任务修订/运行快照，逻辑名仅用于展示；模板更新产生新版本，不改已固定运行。
- 表达式展示的参数必须与实际匹配参数一致，不能显示一个阈值、执行另一个。原生定位继续 resource-id 优先，原生与图像结果不能互相冒充。

**目标接口（技术收敛，不表示现有实现已支持）**

| 接口 | 最小契约 |
| --- | --- |
| 采集快照 | 复用现有调试采集入口，返回 snapshot_id、分辨率、图像摘要与采集时间；无活动会话或设备忙拒绝 |
| POST /templates | `{logical, snapshot_id, region, confidence, confirm_new_version}`；同名未确认返回 409/template_exists，确认后 201 追加版本；区域与阈值按上述规则校验 |
| GET /templates；GET /templates/{logical}/versions | 按 application_id 列出逻辑名、版本、摘要、来源和默认阈值；历史版本只读 |
| POST /templates/{logical}/versions/{version}/matches | `{snapshot_id, threshold}`；返回真实匹配结果；能力不可用返回明确状态，不返回模拟分数 |

现有前端模板登记已使用 snapshot_id、region、logical 并由服务端裁剪，但缺少阈值、版本选择和匹配验证，且按会话隔离；需按本契约扩展，不新增浏览器上传图片通道。

### 9.1 请求身份、并发与幂等

本节是目标契约；不表示现有接口已支持。所有公开路径沿用 `/api/v1` 前缀，表内省略前缀。新增响应字段采用 snake_case，保留既有消费者所需字段；同步调整严格响应模型与前端类型。旧文档 camelCase 示例不能另立协议。

| 操作 | 身份与请求约束 | 响应与冲突 |
| --- | --- | --- |
| POST /tasks | 沿用 §6.1 字段及既有请求幂等键；键绑定规范化创建内容，含应用、名称、类型、平台、构建、套件、环境和 config | 新建沿用任务响应；同键同内容返回原任务。同应用同名但不同配置返回 409/task_configuration_conflict，附 existing_task_id 与差异字段名，禁止无提示复用旧配置；同名同内容可复用已有任务 |
| PATCH /tasks/{id} | 必填 lock_version；config 整份替换；按 §6.1 生成新修订 | 并发失效沿用 stale_version，返回最新对象供刷新；不自动覆盖并发编辑 |
| POST /tasks/{id}/validate | 检查当前配置，成功追加 validated 修订 | 响应的最新修订才是后续执行引用；不能继续提交验证前的草稿 revision_id |
| POST /runs | 浏览器显式提供 §6.2 身份；parent_run_id 仅用于重跑；设备选择使用 device.resource_id | 新建 201，重放 200 并保留 duplicate=true；返回 id/display_id/state，重放可含 outcome；非 validated、跨应用/平台/项目引用拒绝 |
| POST /runs/{id}/cancel | 沿用既有端点，不直接改终态 | 202 表示受理；重复在途请求不增加重复取消事实；已终态返回 state_conflict 并刷新真实终态 |
| POST /runs/{id}/gate-evaluations | 必填 request_key、policy_id、baseline_run_id，均为明确选择；只对可用的 completed 性能组件追加 reanalysis | 新建 201；同键同内容返回原记录并标 duplicate；同键不同输入 409/idempotency_conflict；不因没有 original 改成首次判定 |

- 幂等比较使用规范化业务内容；对象键顺序不产生新操作，修改构建、修订、设备或试算版本则属于不同内容。同一项目、同一操作范围的键在并发与服务重启后仍有效，不能只靠进程内字典。
- 同键不同内容返回 409/idempotency_conflict，保留原对象，不执行新的副作用；唯一约束竞争失败后的回读也须比较指纹。套件快捷运行和向导保留已创建身份，失败恢复从失败步骤重试。
- POST /runs 的类型和固定输入来自修订；本次浏览器请求不使用 overrides。服务端拒绝以 overrides、source_dir、test_paths 或伪造结果字段改写固定输入；内部导入/测试用途与浏览器真执行隔离，不能成为绕过通道。旧客户端若仍依赖 task_id 解析最新修订，兼容入口也须先固定实际 revision_id 并返回，不能在派发时重新解析。
- 同名冲突需要用户选择原任务或另起名称；平台不能替用户默认更换构建/套件。错误 details 只返回可展示标识、缺项与差异字段，不返回敏感配置值。

### 9.2 输入供应与检查的目标接口

| 目标接口 | 最小契约 |
| --- | --- |
| GET /builds；POST /builds | 按 application_id 列出或登记；登记 version/build_key，可带 source_commit/sha256。响应给 id、归属、声明身份与 identity_state=pending/confirmed；同 key 冲突按 §6.0 处理 |
| POST /builds/{id}/identity-checks | 传 resource_id，在互斥下只读安装身份；返回 check_id、设备、checked_at、预期/观测项、match/conflict/unknown 与阻断原因。busy 返回 409/device_busy，不额外访问设备 |
| POST /builds/{id}/confirm-identity | 显式提交该构建的 check_id；仅接受同构建且读取完整、版本一致、尚未被替代的核对结果。确认以原子方式固定基准，重复相同确认幂等，不以另一设备结果覆盖；正式执行仍重新读取 |
| GET /suite-sources；POST /suites | 来源列表只返回预配置 source_id/显示名/适用类型，不暴露宿主绝对目录；登记应用、名称、test_type 和 source_id。纯性能可无代码来源，使用声明式场景 |
| POST /suites/{id}/discover | 复用现有路径；浏览器按 source_id 指向的固定副本发现，不传任意 suite_root。只有副本完整、摘要通过且发现成功才发布版本；失败保留诊断，不发布半成品 |
| POST /suites/{id}/versions | 发布 performance 声明式场景或 joint 完整组合；manifest 含 schema_version、test_type 及类型所需字段。UI 用例由 discover 产生；joint 明确 UI 代码副本/清单与性能采集项、ui_timeout_s，不能引用可变“最新” |
| POST /resources/{id}/readiness | 传 test_type，只检查；返回 checked_at、test_type、总体状态、blocking 与逐项结果/原因。互斥覆盖整个设备访问期；结果不代替正式运行检查 |

以上新端点属于已批准最小输入与检查流程。共享“检查/身份读取”的互斥实现必须服从数据库租约权威并使用新迁移兼容 holder，不伪装成测试运行来污染统计。迁移方案与锁适配通过 §12 技术门槛前，不能把本机锁或 ready 状态检查当作并发安全证明。手动操作及时释放，无法确认设备访问已停止时保留不可分配状态。

### 9.3 完整集合检索与事件恢复

- GET /runs 保留 scope/state/limit，增加 application_id、test_type、q、cursor；scope 缺省表示全部平台，state 为运行七态之一，test_type 为 ui/performance/joint。q 在完整过滤集合检索稳定 display_id、任务名和应用名，匹配规则为文字包含；不将任意输入解释为 SQL 通配表达式。
- 响应保留 items/total，增加 next_cursor/has_more；total 是同过滤条件的完整数量。按 created_at DESC、id DESC 游标分页；cursor 绑定过滤条件、排序和首屏可见的创建水位，失效或不匹配返回 422/invalid_cursor。新增运行由刷新进入；并发状态变更后刷新重建列表，不宣称多次请求是数据库长事务快照。
- 完成报告使用 state=completed 的服务端过滤。任务配置列表沿用任务接口；“最近运行态”过滤须以关联运行查询实现，不能把运行 state 当任务 lifecycle/readiness。URL 保留 scope、application_id、q、test_type、state；切 scope 清除相关筛选与分页，跨页保留仍适用的应用上下文。
- GET /runs/{id} 增加 components、last_sequence；cancel_requested 是持久化事实，不从最近 500 条事件是否出现来推断。列表、详情与 WS 采用同一服务端进度投影；未知为 null，失败/取消不强制变成 100%。
- 复用 GET /runs/{id}/events?after=<sequence>&limit=<1..500>，按 sequence 升序返回；保留 items/total/after，明确此处 total 是本页条数，增加 next_after/has_more。客户端循环补拉至目标水位，按 run_id+sequence 去重。
- WS 保留 snapshot/state/event/finished/ping/pong；snapshot 给 last_sequence 与一致运行投影，持久化事件帧给 sequence。重连先订阅并暂存新帧，再从已确认序号补拉，合并去重；无序号通知仅触发回读，不能凭通知数推进进度。终态以 GET 状态及补拉事件确认，断线不重发启动操作；暂时读取失败不得伪装运行不存在。
- 稳定 display_id 必须持久分配；历史回填只做一次并保持唯一。迁移保留 UUID 访问，不继续以动态 row_number 作为长期编号。

### 9.4 判定、报告与证据的统一来源

- GET /analyses 默认选 original；可用 evaluation_id 显式选择属于该运行的 reanalysis。响应保留既有指标/上下文及 evaluations，并增加 original_evaluation_id、selected_evaluation_id、original_missing；原始缺失时默认选择为空，仍可展示真实指标，不用 latest_reanalysis 兜底。
- 指标继续使用 value、unit、sample_count、supported、missing_reason 等真实字段；新增真实序列注明 metric_key、单位、时间基准和采集窗口。历史序列不存在时返回空集合与原因。跨档案不计算伪百分比。
- 试算所选 baseline_run_id 必须解析到该运行真实 performance 组件、指标快照和资源档案；保存实际 baseline_id/版本/来源组件，不能挂到无关的“应用最新基线”。可从可核实来源建立不可变基线记录，无法核实则拒绝或给明确未判定；不能伪造关联。
- 原始快照记录具体 policy_id/version、baseline_id/version/source_run_id/source_component_id、profile_id/档案内容、比较窗口和阈值；缺项显式为 null 并列出原因。默认解析按 created_at DESC、id DESC 选择最新有效策略/同档案基线，实际版本在执行快照中固定；提交幂等只比较声明的选择意图，不因默认后来变化重建运行。缺策略使用 gate_policy_missing，缺基线使用 baseline_missing；两者同时缺失列出全部原因，不再仅以样本不足或缺策略文案代替。
- 新运行在 finalizing 中完成数据归档、原始计算、组件结论与整体聚合，随后通过唯一状态迁移入口写终态；这些数据库事实与终态事件在同一事务提交。内部判定接受已完整收口的数据，不再依赖先将运行设 completed 后直接 UPDATE outcome。重试依靠原始唯一约束及幂等记录；不能提交 completed 却缺 original 的新性能运行。
- 文件证据先完成完整性检查，再登记可用引用。归档失败按实际错误收敛；已取得的部分证据可在运行详情查看。取消/错误不补造正常 original；已安全完成的组件事实保持可查，整体仍为 cancelled/errored。
- GET /runs/{id}/report 及待实现 export 默认只反映原始运行语义，包含快照来源与缺失标记；不混入未选择的试算。导出使用 JSON、稳定运行编号命名，并遵守同一产物可用性。errored/cancelled 的证据由运行详情及既有产物接口访问，不以完成报告冒充完整验收。

### 9.5 阶段时限、资源安全与兼容

- ui_timeout_s 与 duration_s 仅约束各自执行窗；准备、启动采集、停止、归档分别使用有限的宿主阶段预算，写入执行快照并展示超时阶段。总 deadline 至少覆盖各阶段预算之和；现有 run_timeout_s=3600 不能提前截断合法 3600 秒执行窗。宿主预算不足时在提交/派发前明确拒绝，不能静默缩短已固定时长。预算值和最坏路径须由实施定向测试给证据。
- 安全终态与可分配状态分开：fence 失效拒绝旧拥有者写入，还须阻止其继续访问设备。仅租约过期或数据库释放不能证明旧进程停止；未确认安全收口的设备保持不可分配并说明原因，不自动触发修改连接方式的自愈。
- 旧任务仍可生成新修订；不把绑定过历史运行解释成禁止一切编辑。旧 suite 缺代码副本、旧构建未确认、历史档案或 original 缺失都明确展示；查看历史不强制追认，新执行按新规则补齐。
- 若需迁移，新增迁移并保持当前 0001 原件；回填只使用可核实数据。新响应与严格模型、前端消费同时调整，更新 OpenAPI/接口说明；兼容输入不能绕过固定输入、独占、原始唯一或终态不变约束。本文不替代迁移演练与回退验证，也不授权运行迁移。
