# 领域文档

工程技能探索代码库时应如何消费本仓库的领域文档。

## 探索前先读

- 根目录 `GLOSSARY.md`；若存在 `GLOSSARY-MAP.md`，则按它读取各上下文对应的 `GLOSSARY.md`
- `docs/adr/` 中与当前工作区域相关的 ADR；多上下文仓库还要检查 `src/<context>/docs/adr/`

文件不存在时静默跳过，不提示缺失，也不主动建议创建；由 `/domain-modeling` 在术语或决策真正确定时按需创建。

## 文件结构

单上下文仓库（本仓库）：

```text
/
├── GLOSSARY.md
├── docs/adr/
└── server/、web/
```

## 使用词汇表语言

输出中命名领域概念时（issue 标题、重构提案、假设、测试名称），使用 `GLOSSARY.md` 已定义的术语，不要漂移到词汇表明确避免的同义词。

需要的概念尚未收录时，先判断是自己发明了项目不使用的语言（应重新考虑），还是确实存在缺口（记录给 `/domain-modeling`）。

## 标出 ADR 冲突

输出与现有 ADR 矛盾时显式指出，不要静默覆盖：

> _与 ADR-0007 冲突，但值得重新讨论，因为……_
